# F005 configuration and firmware contract

This reference applies to the investigated F005/GD32F303RET6 board. Verify
board identity and independently calibrate another printer. Exact active
Klipper values live in
[`printer-f005-mainline.cfg`](../configs/klipper-f005/printer-f005-mainline.cfg).

## Configuration

The host uses passive `/dev/ttyS1` at 230400 baud and `restart_method: command`.
Upstream Klipper provides Cartesian motion, extruder, TMC2208 software UART,
X/Y endstops, BLTouch and safe Z homing, bed mesh, heaters, thermistors, fans
and filament sensing. The Linux-process MCU at `/tmp/klipper_host_mcu` exposes
ADXL345 through `/dev/spidev2.0`.

The reference `z_offset: 2.180`, PID, mesh and input-shaper values are scoped to
the investigated printer. They are not universal calibration defaults. See
[configuration](configuration.md) before changing the installed file; existing
HOME configuration is retained and is not automatically migrated by an update.

## Firmware and bootloader invariants

The productive target identifies as `gd32f303xe`: 120 MHz from an 8-MHz external
reference, 64 KiB RAM and the Cortex-M3-compatible instruction subset. Exact
configuration is in
[`f005-gd32f303.config`](../build/klipper-f005/f005-gd32f303.config); the STM32F1
implementation/header reuse does not identify the physical chip as STM32F103.

The application starts at `0x08003000`. Preserve the existing first 12 KiB
bootloader at `0x08000000..0x08002fff`. The linker-visible application region
ends at `0x08040000` (exclusive), with `CONFIG_FLASH_SIZE = 0x3d000`; the
physical chip's upper 256 KiB remains intentionally unused. Do not enlarge or
move this region without separate validation of GD32 FMC behavior.

Packaging reserves raw offsets `+0x200..+0x21f` for board info. The packager
writes compatibility sentinel `mcu0_004_000`, CRC16/CCITT at `+0x20c` and the
32-bit little-endian image length at `+0x20e`. The CRC covers the raw image
with its six CRC/length bytes zeroed. The sentinel is distinct from Stock
`mcu0_005_000` and is not a release number. Preserve it so unchanged Stock
can recognize the different application; do not increment it for releases.

New Candidate runtime identities derive from `VERSION` as
`fre3nder-f005-<VERSION>-0-g<prepared-source-sha>`. Exact target identity,
constants, size and hash belong to the effective Runtime target; the Qualified
record remains independent evidence. Neither version prefixes nor numerical
version ordering may choose an image. Preserve the ordinary shutdown-safe
Klipper reset and productive serial bootloader-request paths.

The current source basis and productive patches are pinned by
[sources.json](../configs/x2000/sources.json); the image packager is
[`scripts/package_f005_firmware.py`](../scripts/package_f005_firmware.py).
The initial port, exact comparison basis and clock/FMC reasoning remain in
[the historical port study](../research/docs/gd32f303-mainline-port.md).

## Current Stock and Gate-2 classification

| Function | Current decision |
| --- | --- |
| Motion, heaters, fans, BLTouch, mesh, filament and ADXL345 | UPSTREAM functionality with the required public GD32/host integration |
| Retained Creality serial bootloader and Stock compatibility sentinel | KEEP as transition invariants |
| Vendor updater orchestration | REIMPLEMENT through the open Fre3nder transition primitives |
| Inactive Creality-only `hx711s`, `dirzctl`, `filter`, `soft_homing` and `fan_feedback` | DROP for the selected open-printer scope |
| Optional PR-Touch/Z compensation (`prtouch_v2`, `z_compensate`) | Outside the current scope; REIMPLEMENT if later needed, as recorded in Gate-2 evidence |
| `bl24c16f`, dependent custom macros and remaining factory/EEPROM dependencies | Omitted from the current configuration; unresolved uses remain UNKNOWN; preserve protected contents |

These decisions apply to the investigated reference and selected open-printer
scope. The exact upstream/public Creality/reference-firmware comparison is
preserved in [Stock analysis](../research/docs/klipper-stock.md). Gate status
remains in [roadmap](roadmap.md#standing-project-gates) and [AGENTS.md](../AGENTS.md).

## MCU lifecycle and qualification boundary

Use [F005 switching](f005-mcu-switching.md) for exact state gates, deployment,
Stock opt-in and failure behavior. F005 remains shared between A/B host slots;
platform OTA never silently flashes it. A recognized Qualified predecessor does
not qualify a new Candidate. MCU-leg qualification does not establish a complete
coordinated Stock/Fre3nder host roundtrip.

Exact first-print, staged, Host-MCU and calibration identities remain in
[hardware validation](../research/docs/f005-hardware-validation.md) and
[the host/config milestone](../research/docs/f005-mainline-config-milestone.md).
